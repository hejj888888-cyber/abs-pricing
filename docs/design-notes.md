# 设计笔记：为什么这样切模块

## 一、为什么分四层而不是一个大文件

定价出问题时，错误可能来自三处：参数不对、现金流算错、瀑布分配错。如果全写在一个函数里，任何一个数看着怪，都只能从头查到尾。

拆成四层后，每一层都能单独验证：

| 层 | 单独验证方式 |
|---|---|
| 资产池 | 只看月供与 SMM/MDR：等额本息月供应等于年金公式结果；CPR=0 时 SMM 必须为 0 |
| 现金流 | **现金流守恒**：池收回总额 = 服务费 + 各档分得现金（`run_case.py` 里每次运行都会校验，残差应为 0） |
| 瀑布 | 顺序偿付下，优先A 余额归零前，夹层不应收到任何本金 |
| 定价 | 反解出的票面，代回算 IRR 应等于目标收益率（本项目实测 3.154% → 3.20%，二分精度内收敛） |

现金流守恒这一条是关键：它是唯一能一次性抓住"钱凭空多出来或凭空消失"的检验。很多看起来正常的 ABS 模型，一算守恒就露馅。

## 二、为什么票面要"反解"

教科书的债券定价是"给定票面算价格"。但做分层结构时，实际的问题是：**这一档要按面值卖给投资者，票面得给到多少？**

两者数学上等价，工程上完全不同：前者一次算完，后者要迭代——票面变了，利息支出变，瀑布分配变，现金流变，收益率又变。所以 `pricing.solve_coupons()` 用二分法：固定其他档的票面，只调这一档，重跑瀑布，看 IRR 是否命中目标。

实践中收敛很快，因为优先A 的现金流几乎不受夹层票面影响（利息支付在前、本金顺序偿付也在前）。如果哪天结构改成按比例偿付，这个近似就不成立了，需要联立求解——这一点写在这里，提醒自己别忘了。

## 三、为什么零依赖

最初想用 numpy/pandas，后来放弃，理由是：

1. 老师要在 GitHub 上看，甚至可能在没装环境的机器上跑。"装了 Python 就能运行"比"跑得快"更重要。
2. 本项目的数据量（24 期 × 3 档）根本用不上向量化。
3. 依赖越少，一年后回来看还跑得动的概率越高。

## 四、已知的建模取舍

| 取舍 | 为什么这样选 | 什么时候必须改 |
|---|---|---|
| 月供按初始余额固定 | 池层面近似，避免逐笔建模 | 基础资产笔数少、期限差异大时（如车贷 ABS）会失真 |
| 利息按月初余额计 | 简化，且偏保守 | 违约集中在月中时误差变大 |
| 回收固定滞后 | 参数少，易解释 | 需要算各档 WAL 精度时（第 4 周改） |
| 单一 CPR / CDR | 先跑通再细化 | 第 2、3 周必须改成期限结构 |
| 次级不设票面 | 符合 residual 档的实际形态 | 若次级对外销售并有固定票面，需改 `mode` 为 solve |

## 五、第 1 周的两次返工（真实数据进来之后）

### 返工一：把参数口径整个换掉

第一版用的是教科书口径——等额本息月供 + CPR（提前还款率）+ CDR（违约率）。

扒了联合资信的两份评级报告才发现，人家披露的量化参数是另外四个：**收益率、核销率、月还款率、购买率**。

这不是名词差异。月还款率把"计划摊还"和"提前还款"合在一起，直接给出每月本金回收占比（19.87%、16.23%）；核销率是静态池实际核销，不是假设的违约概率。我用 CPR/CDR 算出来的东西，跟人家用四参数算出来的东西，根本没得比——**比的是口径，不是能力**。

所以整层重写。代价是现金流引擎和资产池参数全改，测试全部重写；收益是结果终于能放进同一张表对比，也才有了"反解票面与实际发行差 1–2bp"这个验证。

**教训**：拿到对标对象的披露文件之前，不要先写模型。口径是对方的，不是课本的。

### 返工二：次级收益率算到 89%

第一版把每月剩余现金全部当超额收益分给次级，跑出来次级 IRR 89%。

89% 一眼假。查了鼎柚的说明书条款才明白：**次级在优先档清偿完毕前，期间收益按不超过 3%/年计**，超额部分留在信托里，到最后才释放。不做这条约束，等于把次级当成一个 10 倍杠杆的利差收割机。

补上 `income_rate` 与留存释放机制后，回落到 65%（鼎柚）和 36%（海尔）。

**教训**：看到 IRR 离谱，先怀疑结构条款没建对，而不是怀疑数据。真实产品的收益分配条款，往往就写在说明书那几行不起眼的"期间收益"里。

### 顺带修掉的一个指标 bug

原来算 WAL 时，把每月现金流减去利息后的部分全当本金——对次级档来说，超额利差会被误记为本金，WAL 直接算到 2.98 年（实际 1.15 年）。修正方式是把本金流和利息流在瀑布里分开记，指标只取本金流。

这个 bug 不影响 IRR，只影响 WAL 和"本金损失率"，所以很容易蒙混过关——**指标之间要交叉验证，单看一个数看不出来。**

## 六、留给自己的一句话

模型的可信度不来自"跑出了结果"，来自"知道结果在什么条件下不成立"。第八节"假设与局限"不是免责声明，是这份作业真正的分。
