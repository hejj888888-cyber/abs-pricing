# 累计核销守恒：总量与时序分离（第 4 周 P0-1 修复）

> 版本：2026-11-04
> 触发：与 Codex 讨论「AAA 情景累计核销不守恒」，它指出正确拆法是「总量锁定 + 时序分配」，
> 不能按出生月锁定、也不能用当月核销率乘固定权重。本文记录诊断、修复、验证与**修复后新暴露的问题**。

---

## 一、问题

修复前，累计核销与「最终压力率 × 累计放款」对不上：

| 案例 / 情景 | 实际累计核销 | 理论值 `co_final × Σface` | 缺口 |
|---|---|---|---|
| 鼎柚 基准 | 154,021,896 | 157,857,041 | −2.43% |
| 鼎柚 AAAsf | 309,514,325 | 397,459,094 | **−22.13%** |
| 够花 AAAsf | — | — | 同向 |

核销率参数本身没错（够花图表19 明确披露：乘数 5.50 × 调整系数 1.20 = 6.60，
最终压力参数 **29.10%**，与 `charge_off_rate 4.41% × 6.6` 完全一致）。
错的是引擎把三个不同概念混在一起：

1. **`co_final`**：情景下的累计终身损失**总量**；
2. **ramp**：从基准过渡到最终压力的**日历时序**（AAAsf 为 4 个月）；
3. **vintage weights**：终身损失在**资产账龄**上的发生分布。

---

## 二、原文依据

**联合资信《消费金融类资产支持证券评级方法》p.7**

> 「基准情景核销率与压力乘数的乘积就是**最大核销率**。」

> 「设定初始核销率为基准情景核销率，经过 4 个月逐渐升至压力水平……在达到压力水平之后均维持该压力直至交易结束。」

前者是**总量**，后者是**时序**。注意原文只说「逐渐」，没有给过渡路径。

**中债资信方法 p.21–22** 把原则说得更透：

> 「违约时间分布表征了基础资产发生违约后，每年的违约额在**总违约额**中的占比。」

> 「计算第 n 年的新增违约时间分布 Z(n) 为新增违约率除以**总的累计违约率**。」

即：时间分布是总量的分配，**不改变总量**。

---

## 三、修复前错在哪

`abs/cashflow.py` 旧实现：

```python
def life_months(c):                      # ← 用出生月的 co_of(born_month) 定寿命
    return max(int(round((1.0 - c) / mrr)), 1)

def loss_weights(c, born_month):
    n = life_months(c)
    ws = vintage.weights(n, shift=...)   # 归一化后的时序权重
    ...

p = c["face"] * mrr
d = c["face"] * c_m * w                  # ← c_m = co_of(m)，当月核销率
if p + d > rem:                          # ← 余额不足时同比例裁剪
    s = rem / (p + d)
    p *= s; d *= s
```

三处叠加导致缺口：

1. 寿命用**成立月**核销率，月度核销用**当月**核销率 —— ramp 期内两者不一致；
2. 损失后置（Weibull 或高损失率）时，固定还款 `p` 先把余额吃掉，后期 `d` 被裁剪；
3. 裁剪是**同比例**的，本金与损失一起缩水，等于凭空少确认损失。

基准情景 ramp = 0、损失率低，所以只差 2.43%；AAAsf 有 4 个月 ramp、损失率 17.27%，
缺口放大到 22.13%。

## 四、修复方案：总量 / 时序分离

每个队列显式记录两个目标：

```python
loss_target  = face × co_final          # 终身核销总量，锁死
prin_target  = face − loss_target       # 应还本金目标
```

月度处理：

```python
p = min(face × mrr,            prin_target − prin_paid)   # 本金：各自封顶
d = min(loss_target × w[age],  loss_target − loss_rec)    # 核销：各自封顶
```

关键改动：

1. **删除 `p + d > rem` 的同比例 capping**，改为各自独立封顶。两者之和不可能超过
   `face`（`prin_target + loss_target = face`），所以不需要联合裁剪。
2. **队列期数**改用 `ceil((1 − co_final) / mrr)`，不再依赖出生月核销率。
3. **ramp 作为时间调节因子**叠加到基础权重上再归一化：

   ```python
   level = co_of(born + k) / co_final      # 当月相对压力水平
   raw[k] = base_w[k] × max(level, 0)
   w = raw / Σraw                          # 归一化 → 总量不变，只改时序
   ```

   这样 ramp 期内损失确认被压低、之后恢复正常，而终身总量仍是 `loss_target`。
   「逐渐」的具体路径仍是线性插值 —— **显式假设，公开文件没披露**。
4. `VintageCurve.weights()` 保持只负责时序（它本来就已归一化）。

### 极端情景与厚度

| 指标 | 鼎柚 修复前 | 鼎柚 修复后 | 够花 修复前 | 够花 修复后 |
|---|---|---|---|---|
| 极端净损失 | 16.14% | **20.66%** | 22.42% | **30.91%** |
| 反解最小次级厚度 | 9.19% | **14.23%** | 11.28% | **21.01%** |
| 实际次级厚度 | 9.3% | 9.3% | 20.5% | 20.5% |
| 厚度 ÷ 极端净损失（静态覆盖倍数） | 0.58x | **0.45x** | 0.91x | **0.66x** |

两单的含义不同，要分开说：

- **鼎柚**：修复前反解下限 9.19% 已经贴住实际厚度 9.3%，只剩 0.11 个百分点余量；
  修复后 14.23% 比实际厚度高出 4.93pp，**从「刚好过」变成「过不了」**。
- **够花**：修复前反解下限 11.28% 相对实际 20.5% 还有 9.2pp 余量；修复后 21.01%
  反超 0.51pp，**从「有余量」变成「差一点点」**。

两单的静态覆盖倍数（厚度 ÷ 极端净损失，不计超额利差）在修复后都进一步下降
（0.58x→0.45x、0.91x→0.66x）。这个指标本身不含超额利差，所以恒小于 1 不代表
一定违约——反解下限才是含利差的口径。但结论方向已经变了：**极端情景下厚度是第一道
防线、超额利差是第二道，P0-1 修复后第二道防线要承担的量明显变大。**
详见更新后的 `docs/gap-analysis.md` 第四节。

## 七、修复后新暴露的问题：核销率的「适用基数」

这是本轮更重要的发现，且**不能靠改代码解决**。

够花图表19 披露核销率最终压力参数 **29.10%**。两种应用方式给出不同总量：

| 应用基数 | 计算 | 累计核销（万元） |
|---|---|---|
| 仅初始池 | 29.10% × 150,000 | 43,650 |
| 初始池 + 持续购买 | 29.10% × 172,743.88 | **50,268**（本模型走这条） |

披露结果隐含的净损失可以严格推出来（累计投放 − 回收款本金 = 172,743.88 −
131,640.92 = **41,102.96** 万元），除以 (1 − 回收率 2.78%) 得累计核销约 **42,278 万元**
——**比「仅初始池」口径还略低**，更接近「仅初始池」而非「含持续购买」。

但按「同一类资产、同一累计损失率」的逻辑，持续购买买进来的资产也应该按 29.10% 违约，
本模型的「含持续购买」写法才是自洽的。两者矛盾。

可能的解释（公开文件都无法证实）：

1. 评级机构只对初始池计损失，持续购买资产按持有期折算；
2. 持续购买资产的合格标准（利率 ≥20%）意味着更优质，损失率更低；
3. 披露表的「净损失」不是按全期累计，而是某个时点口径。

**这一条列为新的 P0-4，需要向 Codex 求证或继续找材料。不改参数、不调基数来凑。**

### 一个诚实的注记

旧模型的 22% 守恒缺口，**方向恰好抵消了一部分基数差异**，所以够花的对表看起来
「更准」（−11.2%）。修复守恒后缺口填上，基数差异就裸露出来（+23.2%）。
这说明：**之前那个「够花对得很近」的结论，含有一部分偶然**。写在这里，不掩盖。
