# 消费金融 ABS 分层定价工具

《投资银行理论与实践》期末作业 · 选题一

用纯 Python 标准库实现消费金融 ABS 的完整定价链路：**资产池 → 逐月现金流（含循环购买） → 分层瀑布 → 票面反解 → 压力测试 → 分层厚度反解**。

本项目的重点不是"算出一个价格"，而是回答一个具体的差距问题：**我的定价流程和行业头部的定价流程，差在哪一步。**

---

## 一、当前版本（截至第 5 周）

两只有公开披露的消费金融 ABS，参数全部换成**评级报告披露的真实值**：

| 案例 | 发起机构 | 规模 | 收益率 | 核销率 | 月还款率 | 分层 |
|---|---|---|---|---|---|---|
| 鼎柚2025年第三期 | 中原消金 | 15.03 亿 | 21.49% | 3.14% | 19.87% | A/B/C/次级 = 74.4/5.8/10.3/9.2 |
| 够花2025年第二期 | 海尔消金 | 15.00 亿 | 23.95% | 4.41% | 16.23% | A/B/次级 = 71.2/8.3/20.5 |

> 收益率用的是评级报告图表17「现金流模型基准参数」里的**历史静态池基准年化**（21.49% / 23.95%），这是评级机构建模用的口径。发行说明书另给「初始资产池加权平均现行贷款年利率」（21.15% / 23.57%），两者不是同一个东西，模型统一用前者。

### 八个结论

**第一，票面不再反解，改看实现收益率与票面的差。** 面值发行下反解票面是循环论证（详见 `docs/param-calibration.md`），现直接用发行结果的实际票面。鼎柚 A/B/C 票面 1.85%/2.20%/2.75%，模型算出的实现收益率 1.87%/2.22%/2.78%——**每档高 2–3 个基点**，差额来自按月计息与按季付息的口径差，说明现金流结构本身没算错。

**第二，两个量化指标的分母都是「初始放款金额」。** 月还款率（方法 p.6）= 静态池当月收到的本金 / 静态池**初始**放款金额，所以本金回款额近似常数（水平偿还），不是 `余额 × 月还款率` 的几何衰减；改之前模型比披露的优先档预期到期日晚 2–3 个月，改之后差异缩到 **±1 个月**。核销率（方法 p.5）= 逾期 90 天后仍未偿还的**未偿本金余额** / 静态池初始放款金额，是**累计终身损失率而非年化率**——第 4 周才发现的这个口径错误，此前把累计损失系统性低估了一半以上，是模型相对评级机构偏乐观的最主要来源。两者同分母后，队列的**本金摊还期**由 `N = (1 − 核销率) / 月还款率` 决定；核销发生在哪几个月是另一根轴，由时序权重决定（第 5 周把两者拆开，见结论八）。

**第三，核销率口径修正后，累计违约率阈值会被突破——而披露值更接近「触发未反馈」的口径。** 合同口径的分母要**加上历次持续购买的本金**（鼎柚第142项：初始起算日余额 + 各持续购买日购买资产的未偿本金余额之和，累加不扣减），分母确实会膨胀、把分子稀释掉；但核销率由年化改为累计终身口径后，累计违约本金约放大一倍，压力情景下峰值仍达到 **17.27%（鼎柚）/ 29.11%（够花）**，越过首年 5% 阈值。

本模型据此截断循环期 3–4 个月，购买额随之从 7.98 亿掉到 3.56 亿（鼎柚）、从 2.90 亿掉到 1.38 亿（够花）；而评级报告图表20/21 披露的持续购买支出是在**接近完整循环期**的量级上给出的。这提示评级机构的压力测试**很可能没有把触发机制反馈回现金流**。

**为什么只写「很可能」**：联合资信方法 p.12–13 要求压力测试覆盖触发机制，但没披露逐月判定的先后顺序，两种做法会差出上面那个量级。公开文件不足以判定，所以不能把「未叠加」写成结论。本报告的对表统一在「不截断」口径下进行（否则与披露值不可比），触发机制另作独立章节评估。见 `docs/inflow-calibration.md` 第四节。

**第四，修复核销守恒后，「不违约下限」反超了实际厚度。** 反解「极端情景下优先档不违约」所需的最小次级厚度：鼎柚 **14.23%**、够花 **21.01%**；市场实际只做到 9.3% 和 20.5%，覆盖倍数 **0.45x / 0.66x**，两单都跌破 1。鼎柚的极端净损失（20.66%）穿透次级厚度 11.36 个百分点，够花（30.91%）穿透 10.41 个百分点，差额由 18.68% / 21.25% 的超额利差吸收。

这个结论与第 4 周版本相反，原因不是市场结构变了，而是**旧模型的核销守恒缺口（AAAsf 情景少计 22%）把极端损失系统性压低了**。修复后极端净损失从 16.14% / 22.42% 升到 20.66% / 30.91%，反解下限随之抬升。所以正确说法不是「厚度只要 0.5% 就够」，而是：**极端情景下厚度覆盖不了全部损失，超额利差是第二道防线，厚度只是第一道**。详见 `docs/loss-conservation.md` 第六节。

**第五，次级收益率只能给区间，给不出点估计。** 说明书分配顺序末端是「先支付后端服务报酬，再由次级取得剩余收益」，而后端报酬的计算方式由《收费文件》约定，该文件不公开。取后端报酬占期末剩余的 0% 与 100% 两种极端：

| | 下界 | 上界 |
|---|---|---|
| 鼎柚次级收益率 | 1.87% | **110.28%** |
| 够花次级收益率 | 1.7% | **61.6%** |

区间跨度这么大，恰好量化了「缺一份文件」的代价。这是本报告最大的单点不确定性，也是行业实务与公开披露之间最实在的一道墙。

**第六，与评级机构对表：分配端精确成立，流入端有硬 GAP。** 图表20/21 的流入端合计代入瀑布，算术上必然复现各档实付（鼎柚 111900 / 6267.13 / 0 / 0；够花 106800 / 12400 / 3963.12），说明瀑布顺序、税费、次级期间收益封顶都与真实结构一致。模型侧的优先A 实付在两单都与披露精确一致（111,900.12 / 106,800.00）。

修复核销守恒后，流入端偏差**鼎柚改善、够花反转**：鼎柚净损失由 −43.2% 收窄到 −27.1%，够花由 −11.2% 变成 **+23.2%**。够花的反转说明之前「对得很近」含有一部分偶然——旧模型 22% 的守恒缺口恰好抵消了「核销率适用基数」的口径差（见结论八）。鼎柚的持续购买支出仍是硬 GAP：按披露购买率 55% 只能买 7.98 亿，**即使购买率开到 100%（现金守恒上限）也只有 17.04 亿，低于披露的 20.17 亿**。量化到这一步，比调参把数字凑上去更诚实。详见 `docs/inflow-calibration.md` 与 `docs/loss-conservation.md`。

**第七，回收时间分布做了，但结论是「影响小到可以忽略」。** 把回收款从「第 6 月一次性到账」改成按 1–6 月分布，两单优先A WAL 极差都只有 0.0001 年（约 0.04 天），次级实现收益率极差 0.03–0.04 个百分点。原因不是模型不敏感，而是核销后回收率只有 3.31% / 2.78%，回收款占现金流比重太低。同时确认了一件更重要的事：**回收时序不是中性的**——回收款进入循环期可购买资金，改到账月份会改购买额与队列规模，所以第 2 周账龄曲线那套「总量不变、两遍跑法」不能套用。这属于「做了才发现没那么重要」，如实记录；实现与逐行退化验证见 `docs/recovery-timing.md`。

**第八，核销守恒是「总量锁死 + 时序分配」，修复它顺带暴露了一个更深的基数问题。** 之前引擎把三件事混在一起：终身损失总量、ramp 过渡节奏、账龄时序分布。后果是 AAAsf 情景累计核销只有「最终压力率 × 累计放款」的 78%（少计 22%）。按联合资信方法 p.7「基准核销率 × 压力乘数 = 最大核销率」与中债资信 p.21「时间分布不改变总量」，改成每个队列锁定 `loss_target = face × co_final`、ramp 与 vintage 只负责分配月份；五个情景的累计核销偏差全部降到 **0.000000%**，测试 58 → 66 项。

修复后露出新问题：够花图表19 披露的核销率最终压力参数是 **29.10%**（乘数 5.50 × 调整系数 1.20，参数本身没错）。若按「初始池 + 持续购买」应用，累计核销 50,268 万元；披露结果隐含的只有约 42,276 万元，更接近「仅初始池」口径。**核销率在循环购买结构下的适用基数是未公开的**——这一条列为新 GAP，不调参数、不改基数去凑。见 `docs/loss-conservation.md` 第七节。

## 二、怎么跑

零依赖，只需要 Python 3.8+。

```bash
python scripts/run_case.py --all        # 跑全部案例 + 横向对比
python scripts/run_case.py              # 只跑鼎柚
python scripts/run_case.py --case cases/gouhua_2025_2.json
python -m unittest discover -s tests -v # 66 项测试
```

产出：

- `output/<case>_report.md`：完整定价报告（八个部分，含参数来源表）
- `output/<case>_schedule.csv`：逐月现金流明细，可直接导入 Excel 复核

## 三、模型结构

```
abs/pool.py       资产池：评级机构四参数口径（收益率/核销率/月还款率/购买率）
abs/vintage.py    账龄曲线：Weibull 累计违约曲线，把恒定核销率换成爬坡—平台形态
abs/cashflow.py   现金流：循环购买期（本金再投资、余额不变、不分配本金）+ 摊还期（按月还款率摊还）
abs/waterfall.py  瀑布：服务费→各档利息→各档本金→次级期间收益封顶→超额留存期末释放
abs/trigger.py    触发：多条件判定，区分加速清偿事件与违约事件
abs/pricing.py    定价：反解票面、IRR、WAL、本金损失率
abs/structure.py  结构：反解"优先档不违约"所需的最薄次级厚度
```

### 三个关键设计

**参数口径换成评级机构的。** 第一版用教科书的"等额本息 + CPR/CDR"，后来发现评级报告披露的是"收益率/核销率/月还款率/购买率"四个参数。口径不同，算出来的厚度根本没得比——比的是口径差异，不是能力差异。所以第 1 周就把参数体系换成对方的口径。

**票面从"反解"改成"实测"。** 教科书写"给定票面算价格"，但分层设计的实际提问是"这一档要按面值卖给投资者，票面得给到多少"。第 1 周用 `solve_coupons()` 二分法反解；第 2 周拿到发行结果公告后，发现反解本质是让票面趋近目标收益率，而目标收益率又取自实际发行结果——**属循环论证，已改为直接用实际票面（`mode: fixed`），报告实现收益率**。详见 `docs/param-calibration.md`。

**账龄曲线只重整时序，不改损失总量。** 两遍跑：先按恒定核销率得总量 L，再按曲线把同一个 L 分发到各月。这样结果差异纯粹来自时序效应，可与"总量估错"分开归因。


## 四、验证

```bash
python -m unittest discover -s tests -v
```

66 项测试覆盖九类易错点：

| 类型 | 检查什么 |
|---|---|
| 口径换算 | 年化核销率 → 月度核销率的折算是否自洽；账龄曲线总量守恒 |
| 现金流 | 循环期余额是否维持不变、**是否一分本金都不分**；摊还期余额是否单调下降至零 |
| 守恒 | 池收回总额 = 服务费 + 各档分得现金流（每次运行强制校验，残差 0.00 元） |
| 收敛与单调 | 票面反解是否命中目标收益率；次级越厚，优先档损失不得变大 |
| 触发阈值 | 5%/8% 分段切换点是否准确；等于阈值不触发；上调系数是否如期提前触发 |
| 触发分类 | 鼎柚 (129)(f) 预期到期日本金属**加速清偿事件**（不是违约事件）；同一条件不重复记录 |
| 口径定义 | 月还款率按**初始放款金额**计提（水平偿还，非几何衰减）；累计违约率分母含持续购买本金 |
| 回收分布 | 默认定点滞后与显式 one-hot **逐行等价**；任意分布下累计回收 = 回收率 × 累计核销；余额归零后尾部回收不被截断 |
| 核销守恒 | 任一情景下累计核销 = `co_final × (初始池 + 累计购买)`，偏差 0.000000%；ramp 只改时序不改总量；高损失率下无 capping 缺口 |

## 五、参数来源与假设

| 类别 | 鼎柚2025三期 | 够花2025二期 |
|---|---|---|
| 披露参数（直接引用） | 收益率、核销率、月还款率、购买率、资产池余额、分层占比、**持续购买期 8 个月**、**回收率 3.31%**、**回收周期 6 个月** | 同左，另含 A/B 档实际票面；**持续购买期 6 个月**、**回收率 2.78%**、**回收周期 6 个月** |
| 假设参数（仍未取到） | 回收款在 6 个月内的分布形状、ramp 过渡路径、压力乘数在区间内的具体选取依据、后端服务报酬算法（《收费文件》不公开） | 同左 |

- 量化参数来源：联合资信信用评级报告（链接见各 `cases/*.json` 的 `source` 字段）。
- **回收率与回收周期**来自中债资信评级报告《表15：压力测试的基准条件和加压幅度》基准条件；原件使用「回收周期（月）」而非「回收滞后」，本模型按回收周期理解并映射到 `recovery_lag_months`。
- **持续购买期**来自发行说明书。原件用「持续购买」而非教科书的「循环购买」，本模型沿用「循环购买」这一通用术语，但数据取自「持续购买」条款。
- 完整校准过程与影响量化见 `docs/param-calibration.md`。
- **每个参数在报告第一节都标了是"披露"还是"假设"**，假设项在第八节逐条说明影响。

## 六、已知局限

1. 循环期按队列推演（cohort），买入的资产独立生息、摊还、违约；购买额按「到账本金 × 购买率」并以本金分账户余额封顶。**购买率的语义与原件不完全一致**：方法 p.6 定义的是「当月新增资产规模 / 上月可用于购买的资金」，含上期本金账户留存与收入账户转入，本模型简化为「当期到账本金 × 购买率」。这是鼎柚持续购买额买不够的直接原因之一。
2. 真实交易在循环期按季付息，本模型按月计息并当月支付，会小幅高估优先档现金流的时间价值。
3. 账龄曲线已接入，**基准情景不启用**。理由已更新：此前写的「叠加曲线少计 44%」是旧引擎（年化核销率 + 单余额标量）的数字，在 cohort 引擎下从未复测；修复守恒后实测启用 Weibull 与均匀摊铺的累计核销只差约 2.3 个百分点，且两者都精确守恒。当前真正的理由是：公开报告只给静态池累计违约率的**图形**、没有逐月数据点，`tau`/`k` 无法从原件精确取得，故主基准用总量守恒的均匀时序，Weibull 仅作显式假设的敏感性分析。见 `docs/loss-conservation.md` 第八节。
4. 未建模混同风险、服务机构替换、外部增信（差额支付承诺等）。经核对，两单说明书均**未设外部差额支付承诺**；鼎柚图示中的"差额补足"是信托本金账户向收入账户的内部划转。
5. 触发机制已按原件实现为多条件、并区分加速清偿事件与违约事件，累计违约率按合同口径直接计算（分子 = 违约贷款未偿本金，分母 = 初始余额 + 累计持续购买本金），不再需要「违约→核销」的上调系数（`default_uplift` 保留但仅作敏感性试算）。「优先档本金未按期足额分配」一条实现但默认关闭，原因是模型清偿月与披露的预期到期日仍有 **1–2 个月偏差、方向因单而异**（鼎柚偏慢、够花偏快），用模型口径判会把口径差误报成违约事件。详见 `docs/trigger-engine.md`。
6. **拿不到逐笔静态池数据**——这是结构性缺口，不是能力问题，详见 `docs/gap-analysis.md`。
7. 回收时间分布已实现为显式事件调度（不再有尾部截断），但公开文件只给「回收周期 6 个月」与回收率，**没有披露分布形状**；默认定点滞后，非空分布均为显式假设、仅作敏感性分析。本单实测影响可忽略，见 `docs/recovery-timing.md`。
8. **核销率的适用基数未公开**。核销率乘在「初始池」还是「初始池 + 持续购买」上，公开文件没有说；本模型取后者（同类资产同一累计损失率，逻辑上自洽），而披露结果隐含的净损失更接近前者。这一条直接决定够花的净损失是 +23.2% 还是别的量级，是当前最大的口径不确定性。见 `docs/loss-conservation.md` 第七节。
9. 联合资信方法 p.7 还有一条**未建模**的兜底条款：「对最大核销率设定了一个最低值，当基准情景核销率乘上相应乘数后小于该最低值时，要以该最低值作为最大核销率」。两单乘数后均远高于任何合理下限，暂不影响结果，但兜底值本身未披露。
