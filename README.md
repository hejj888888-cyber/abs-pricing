# 消费金融 ABS 分层定价工具

《投资银行理论与实践》期末作业 · 选题一

用纯 Python 标准库实现消费金融 ABS 的完整定价链路：**资产池 → 逐月现金流（含循环购买） → 分层瀑布 → 票面反解 → 压力测试 → 分层厚度反解**。

本项目的重点不是"算出一个价格"，而是回答一个具体的差距问题：**我的定价流程和行业头部的定价流程，差在哪一步。**

---

## 一、当前版本（第 3 周完成）

两只有公开披露的消费金融 ABS，参数全部换成**评级报告披露的真实值**：

| 案例 | 发起机构 | 规模 | 收益率 | 核销率 | 月还款率 | 分层 |
|---|---|---|---|---|---|---|
| 鼎柚2025年第三期 | 中原消金 | 15.03 亿 | 21.15% | 3.14% | 19.87% | A/B/C/次级 = 74.4/5.8/10.3/9.2 |
| 够花2025年第二期 | 海尔消金 | 15.00 亿 | 23.57% | 4.41% | 16.23% | A/B/次级 = 71.2/8.3/20.5 |

### 五个结论

**第一，票面不再反解，改看实现收益率与票面的差。** 面值发行下反解票面是循环论证（详见 `docs/param-calibration.md`），现直接用发行结果的实际票面。鼎柚 A/B/C 票面 1.85%/2.20%/2.75%，模型算出的实现收益率 1.87%/2.22%/2.78%——**每档高 2–3 个基点**，差额来自按月计息与按季付息的口径差，说明现金流结构本身没算错。

**第二，月还款率的分母是初始放款金额，不是当期余额。** 这是本期改掉的最大的一个错。《联合资信 消费金融类资产支持证券评级方法》p.5：月还款率 = 静态池当月收到的本金 / 静态池**初始**放款金额。所以本金回款额近似常数（水平偿还），不是 `余额 × 月还款率` 的几何衰减。改之前模型比披露的优先档预期到期日晚 2–3 个月，改之后差异缩到 **±1 个月**（鼎柚优先A 第 12 月，与披露完全一致）。评级方法还写明：正常摊还期本金是先积累、按约定日偿还，**只有触发信用事件后才过手**——我原来摊还期每月过手，也是错的。

**第三，循环购买结构里，累计违约率条款几乎是「死条款」。** 合同口径的分母要**加上历次持续购买的本金**（鼎柚第142项：初始起算日余额 + 各持续购买日购买资产的未偿本金余额之和，累加不扣减）。持续购买期内每月购买额约等于当月本金回收额，分母从 15.03 亿一路涨到 39.32 亿，把分子稀释掉一半以上：

| 鼎柚 | 占初始余额口径 | 合同口径 | 首年阈值 |
|---|---|---|---|
| 压力情景峰值 | 6.24% | **2.68%** | 5% |
| 极端情景峰值 | 9.81% | **4.46%** | 5% |

三情景全部不触发。这不是参数估错，是循环结构本身的性质——新资产不断注入分母，单笔违约在比率上被持续稀释。真正的加速清偿风险因此集中在服务机构解任、发起机构丧失清偿能力这些**非量化**条件上，它们与资产池表现无关，只能靠情景开关注入。够花的阈值更宽松（次年 10%），但核销率更高，极端情景在第 8 月触发。

**第四，分层厚度不是由「不违约」决定的。** 反解「极端情景下优先档不违约」所需的最小次级厚度，两单都只要 **0.50%**；市场实际做到 9.3% 和 20.5%，是极端情景净损失的 0.96 倍和 1.52 倍。鼎柚的极端净损失（9.68%）已经**穿透**次级厚度 0.43 个百分点，但次级实际损失仍为 0%——差额全部由 18.68% 的超额利差吸收。这段缓冲是评级机构的模型误差要求，披露文件里看不到。

**第五，次级收益率只能给区间，给不出点估计。** 说明书分配顺序末端是「先支付后端服务报酬，再由次级取得剩余收益」，而后端报酬的计算方式由《收费文件》约定，该文件不公开。取后端报酬占期末剩余的 0% 与 100% 两种极端：

| | 下界 | 上界 |
|---|---|---|
| 鼎柚次级收益率 | 1.87% | **110.28%** |
| 够花次级收益率 | 1.7% | **61.6%** |

区间跨度这么大，恰好量化了「缺一份文件」的代价。这是本报告最大的单点不确定性，也是行业实务与公开披露之间最实在的一道墙。

## 二、怎么跑

零依赖，只需要 Python 3.8+。

```bash
python scripts/run_case.py --all        # 跑全部案例 + 横向对比
python scripts/run_case.py              # 只跑鼎柚
python scripts/run_case.py --case cases/gouhua_2025_2.json
python -m unittest discover -s tests -v # 48 项测试
```

产出：

- `output/<case>_report.md`：完整定价报告（八个部分，含参数来源表）
- `output/<case>_schedule.csv`：逐月现金流明细，可直接导入 Excel 复核

## 三、模型结构

```
abs/pool.py       资产池：评级机构四参数口径（收益率/核销率/月还款率/购买率）
abs/vintage.py    账龄曲线：Weibull 累计违约曲线，把恒定核销率换成爬坡—平台形态
abs/cashflow.py   现金流：循环购买期（本金再投资、余额不变、不分配本金）+ 摊还期（按月还款率摊还）
abs/waterfall.py  瀑布：服务费→各档利息→各档本金→次级期间收益封顶→超额留存期末释放
abs/trigger.py    触发：多条件判定，区分加速清偿事件与违约事件
abs/pricing.py    定价：反解票面、IRR、WAL、本金损失率
abs/structure.py  结构：反解"优先档不违约"所需的最薄次级厚度
```

### 三个关键设计

**参数口径换成评级机构的。** 第一版用教科书的"等额本息 + CPR/CDR"，后来发现评级报告披露的是"收益率/核销率/月还款率/购买率"四个参数。口径不同，算出来的厚度根本没得比——比的是口径差异，不是能力差异。所以第 1 周就把参数体系换成对方的口径。

**票面从"反解"改成"实测"。** 教科书写"给定票面算价格"，但分层设计的实际提问是"这一档要按面值卖给投资者，票面得给到多少"。第 1 周用 `solve_coupons()` 二分法反解；第 2 周拿到发行结果公告后，发现反解本质是让票面趋近目标收益率，而目标收益率又取自实际发行结果——**属循环论证，已改为直接用实际票面（`mode: fixed`），报告实现收益率**。详见 `docs/param-calibration.md`。

**账龄曲线只重整时序，不改损失总量。** 两遍跑：先按恒定核销率得总量 L，再按曲线把同一个 L 分发到各月。这样结果差异纯粹来自时序效应，可与"总量估错"分开归因。


## 四、验证

```bash
python -m unittest discover -s tests -v
```

48 项测试覆盖七类易错点：

| 类型 | 检查什么 |
|---|---|
| 口径换算 | 年化核销率 → 月度核销率的折算是否自洽；账龄曲线总量守恒 |
| 现金流 | 循环期余额是否维持不变、**是否一分本金都不分**；摊还期余额是否单调下降至零 |
| 守恒 | 池收回总额 = 服务费 + 各档分得现金流（每次运行强制校验，残差 0.00 元） |
| 收敛与单调 | 票面反解是否命中目标收益率；次级越厚，优先档损失不得变大 |
| 触发阈值 | 5%/8% 分段切换点是否准确；等于阈值不触发；上调系数是否如期提前触发 |
| 触发分类 | 鼎柚 (129)(f) 预期到期日本金属**加速清偿事件**（不是违约事件）；同一条件不重复记录 |
| 口径定义 | 月还款率按**初始放款金额**计提（水平偿还，非几何衰减）；累计违约率分母含持续购买本金 |

## 五、参数来源与假设

| 类别 | 鼎柚2025三期 | 够花2025二期 |
|---|---|---|
| 披露参数（直接引用） | 收益率、核销率、月还款率、购买率、资产池余额、分层占比、**持续购买期 8 个月**、**回收率 3.31%**、**回收周期 6 个月** | 同左，另含 A/B 档实际票面；**持续购买期 6 个月**、**回收率 2.78%**、**回收周期 6 个月** |
| 假设参数（仍未取到） | 服务费率 0.5%/年、摊还期上限 12 个月 | 同左 |

- 量化参数来源：联合资信信用评级报告（链接见各 `cases/*.json` 的 `source` 字段）。
- **回收率与回收周期**来自中债资信评级报告《表15：压力测试的基准条件和加压幅度》基准条件；原件使用「回收周期（月）」而非「回收滞后」，本模型按回收周期理解并映射到 `recovery_lag_months`。
- **持续购买期**来自发行说明书。原件用「持续购买」而非教科书的「循环购买」，本模型沿用「循环购买」这一通用术语，但数据取自「持续购买」条款。
- 完整校准过程与影响量化见 `docs/param-calibration.md`。
- **每个参数在报告第一节都标了是"披露"还是"假设"**，假设项在第八节逐条说明影响。

## 六、已知局限

1. 循环期内假设购买率 100%、资产池余额严格不变，未刻画资产置换质量下降与合格资产不足。
2. 真实交易在循环期按季付息，本模型按月计息并当月支付，会小幅高估优先档现金流的时间价值。
3. 账龄曲线已接入，但**未做 cohort 追踪**：循环期内买入的新资产没有独立账龄，全池共用一条曲线，锚点口径（入池起算 vs 摊还起算）无法由披露文件判定。曲线形态本身来自评级报告静态池图的目视读数，非回归拟合。详见 `docs/vintage-curve.md`。
4. 未建模混同风险、服务机构替换、外部增信（差额支付承诺等）。经核对，两单说明书均**未设外部差额支付承诺**；鼎柚图示中的"差额补足"是信托本金账户向收入账户的内部划转。
5. 触发机制已按原件实现为多条件、并区分加速清偿事件与违约事件，但「累计违约率 = 累计核销率 × 上调系数」中的**上调系数无实证支撑**（取 1.0 意味着忽略违约与核销的时间差，触发偏晚）；「优先档本金未按期足额分配」一条实现但默认关闭，原因是模型摊还速度比披露的预期到期日慢 2–3 个月，用模型口径判会把口径差误报成违约事件。详见 `docs/trigger-engine.md`。
6. **拿不到逐笔静态池数据**——这是结构性缺口，不是能力问题，详见 `docs/gap-analysis.md`。
