# 消费金融 ABS 分层定价工具

《投资银行理论与实践》期末作业 · 选题一

用纯 Python 标准库实现一只消费金融 ABS 的完整定价链路：**资产池 → 逐月现金流 → 分层瀑布 → 票面反解 → 压力测试 → 分层厚度反解**。

本项目的重点不是"算出一个价格"，而是回答一个具体的差距问题：**我的定价流程和行业头部的定价流程，差在哪一步。**

---

## 二、怎么跑

零依赖，只需要 Python 3.8+。

```bash
python scripts/run_case.py
```

跑完会在控制台打印三情景结果，并在 `output/` 下生成：

- `consumer-abs-base_report.md`：完整定价报告（Markdown）
- `consumer-abs-base_schedule.csv`：逐月现金流明细（可直接导入 Excel 复核）

改参数只需编辑 `cases/consumer_abs_base.json`，不用动代码。

### 怎么验证它算得对

```bash
python -m unittest discover -s tests -v
```

11 项冒烟测试，覆盖最容易错的四件事：年金公式、SMM/MDR 换算、现金流守恒、票面反解是否命中目标收益率。全部通过才提交。

## 三、模型结构（四层，逐层可单独验证）

```
abs/pool.py       资产池：8 个参数 → 月供、SMM、MDR
abs/cashflow.py   现金流：计息 → 计划摊还 → 早偿 → 违约 → 回收（滞后）
abs/waterfall.py  瀑布：服务费 → 各档利息 → 各档本金 → 剩余归次级；支持顺序/按比例+加速清偿触发
abs/pricing.py    定价：给定目标收益率反解票面、IRR、WAL、损失率
abs/structure.py  结构：反解"夹层不违约"所需的最薄次级厚度
```

### 一个关键设计：票面是"反解"出来的

常规做法是给定票面算价格；分层设计的实际提问方式是"这一档要卖给投资者，票面得给到多少"。所以 `pricing.solve_coupons()` 用二分法反解：给定目标收益率 → 调整票面 → 重跑瀑布 → 看 IRR 是否等于目标 → 收敛。这也是投行做结构时的真实动作。

## 四、当前结果（合成基准参数，待替换真实产品）

| 档位 | 占比 | 票面 | 目标收益率 | WAL | 极端情景本金损失 |
|---|---|---|---|---|---|
| 优先A | 75% | 3.15% | 3.20% | 0.59 年 | 0.00% |
| 夹层 | 13% | 5.37% | 5.50% | 1.25 年 | 0.00% |
| 次级 | 12% | — | 剩余收益 | 2.55 年 | 39.28% |

三个情景的资产池净损失：基准 3.56% / 压力 8.54% / 极端 15.46%。

**核心发现（也是 GAP 的入口）**：极端情景下净损失 15.46% 已经超过次级 12% 的厚度，静态看夹层应当受损；但模型实际跑出来夹层零损失，因为 13.02% 的超额利差先把损失吃掉了。反解得到的"最小次级厚度"只有 5.12%。

而市场上真实的次级厚度普遍在 10%–15%。**这个差额不是算错了，而是行业第一做的事我没做**——评级机构的损失覆盖倍数、循环购买期、服务机构替换、混同风险，这些因素共同把厚度顶到了 10% 以上。差距清单见 `docs/gap-analysis.md`。

## 五、已知局限（如实列出，不掩饰）

1. 计划摊还额按初始余额的等额本息月供固定，早偿/违约导致余额加速下降时不重算月供——池层面近似。
2. 利息按月初余额计，当月违约资产当月仍计息。
3. 回收按固定回收率与固定滞后处理，未刻画回收的时间分布。
4. 票面为面值发行下的反解值，未做询价、簿记环节的价差调整。
5. 未计入税费、中介费用与流动性溢价。
6. **参数目前是行业常见区间内的合成值，尚未替换为真实产品的发行说明书参数**（第 1 周任务，见 `cases/README.md`）。
